# 空間分配與視覺分離

用於圖示線條擁擠、部件近接、內孔縮小或整顆過黑的設計與複審。先讀目前幾何的線寬、角型與光學尺寸；本文件補充造型工藝的墨線間距規則，不取代結構接縫及遮擋避讓。

## 留白與墨線一起構造

圖示的內孔、開口及部件之間的空白共同決定辨識度。幾何分離不等於視覺分離：近接、平行與連續的走向會促使視覺把筆畫分組；小尺寸反鋸齒與對比又會降低窄縫的清晰度。即使大圖能看出縫隙，原生大小仍可能融合為厚邊或黑塊。

先把主輪廓、必要空腔與部件間的空白通道排好，再加入內線。不要把每個零件各自畫完整後硬塞進同一畫布，也不要把所有物件機械地塞進同寬外框。辨識力弱的細節應讓位給關鍵負形。

對每個接近的位置，先判斷三種關係：

- **結構相連**：窗框、鉸鏈、桿與機身等應接在一起；接點收口乾淨且不形成墨團，不為增加空白切斷構造。
- **刻意分離**：口袋與外殼、油管與泵身的平行段、輪胎與上方窗框等需要穩定空白；端帽或轉角不能吃掉通道。
- **前後遮擋**：前景確實遮住後景時才採用外輪廓等距避讓；不要把一般內部擁擠都改成 knockout，或用白描邊遮住。

## 局部縫隙、空腔與整顆節奏

不能只看外接框、全圖平均墨量或最小距離的一個數字。逐顆找最容易合併的區域：

1. **長平行狹縫**：兩條筆畫長距離貼近，會被看成厚邊。短暫轉角的窄處與整段窄走廊需要不同判斷。
2. **角落與楔形空白**：斜線靠近外框、圓角附近的折返、三線匯聚，會讓本來規整的中心距離變成尖細負形。檢查整個可見區域，不只量水平距離。
3. **被雙邊描邊吃掉的內孔**：門窗、環孔和小燈圈要看描邊後剩下的空腔。必要孔先放大／移位；非必要空心細節可刪除或改成有語意依據的實心點。
4. **局部擁擠與旁邊閒置空間**：一側擠成一團，另一側卻很空，通常應重分配部件，而非把整顆放大。比較上／下、內／外、前／後的空白節奏及視覺重心。
5. **鄰近相似訊號**：重複短線、小圈或接近閉合的端點，可能被視覺補成另一個物體。清楚的部件分組比機械等距重要。

同家族保持共同的疏密與層級，但不要求每個縫隙數值相同。窄長孔、三角孔、圓孔與開放缺口的可讀性不同；局部光學補償須有可見理由。

## 在原生座標上做空間預算

局部平行筆畫可用 `可見淨距 ≈ 中心線距離 − (線寬一 + 線寬二) / 2` 初查；圓孔內徑約為 `2r − 線寬`。這些只是排查估算，斜線、端帽、曲線和尖角仍須看實際墨線與 raster。

例如 24 單位稿中的兩線中心距離為 2，縮到原生 16 後只有約 1.333px；以 1.25px 描邊，淨距僅約 0.083px。中心線明明不同，原生卻幾乎沒有可用空白。不能把這種情況記成「有間距」而放行。

專案 `gap` 與既有審查目標是開始設計的依據，不是事後保證。獨立部件之間只剩亞像素狹縫，或必要孔只剩反鋸齒亮點時，必須退回複審；即使超過 1px 也不自動代表比例或疏密良好。圖稿與來源的線寬不同時，分別按其實際墨線看，不強行改成同一描邊。

16px 可以改部件位置、比例、孔徑與數量，不能只刪一筆裝飾後就宣稱光學尺寸完成。遇到 24px 勉強分開、16px 黏合的稿，回頭重分配整個結構；20px 也需獨立查看，不能假定兩端成立就會自動成立。

### 框內套框：先確認容得下，再畫零件

背包前袋、車窗、儀表、門板等不能只按外框寬度的百分比縮出內框。在穿過兩側直壁的截面上，若外框總墨線寬度為 W、外框線寬為 sₒ、內框線寬為 sᵢ，內框與外框左右各留淨距 g，內框剩餘孔寬為 h，則需要 `W ≥ 2sₒ + 2sᵢ + 2g + h`。這是平行直壁的空間預算；圓角、曲面與端帽還會局部壓縮空白，須另看實際輪廓。

例如原生總寬 8px、內外描邊均 1.25px，即使暫以每側 1px 作設計假設，內孔也只剩 1px。這個算例不是全庫間距標準，而是提醒：小框內再套完整小框，可能在加入細節前就已耗盡空間。此時應比較共享底邊的口袋、開放分界、較寬主體或刪去次要框線，而不是把每個零件再縮小一次。

同樣檢查縱向截面；左右夠寬不代表底部通道成立。曲面收窄處和圓角內側尤其要看空白是否突然夾成細尖。修改圓角或線寬後重算這些局部空間，不能沿用另一個角型的通過結論。

## 修正順序

先辨識造成擁擠的主因，優先選擇能保留語意的結構修正：

1. 重排部件位置、層級與比例，利用閒置空間；放大必要空腔、拉開應分離的輪廓。
2. 移除次要分割，合併可由一條共同邊界交代的構造；不要保留兩條近乎重合的完整外框。
3. 為小尺寸改拓撲：例如減少窗格、簡化口袋構造、取消非必要的空心小件；保留辨識以及有價值的構造、姿態線索。底足、肩部等可融入外輪廓，不因它們不是唯一辨識依據便直接刪除；詳見[物件語意與形態保真](craft.md#物件語意與形態保真)。
4. 修正局部收筆、圓角與線段長度，再看空白通道是否連續、接點是否仍成立。
5. 結構已合理而局部視覺重量仍失衡時，才考慮有紀錄的局部線寬補償。不要先縮細全圖、淡化擁擠部位、增加畫布周圍留白或把圖示縮小，來掩蓋內部配置問題。

## 與成熟圖稿並列

每份來源保留自己的 viewBox、原始描邊與比例，與 Master 在相同 CSS 16／20／24px、相同顏色與背景比較。來源只顯示 24px，而 Master 看 16px，不能當作小尺寸疏密的直接證據。放大診斷另列並註明倍率。

先看原生圖的完整輪廓與部件分組，再放大定位原因。具體記錄來源如何用較少內線、更大的孔、更開放的視角或共同邊界得到清楚分離；自己的哪段未做到、採取什麼修正。不能只說「比來源更密」或「兩者都有同一零件」。來源本身也可能擁擠，不因成熟圖庫的名義免於判斷。

檢查淺底、深底、低對比與同家族文字情境，包含實際原生位置及 DPR 1／2。審稿頁避免 CSS 縮放或分數位置造成額外糊化；若聊天預覽縮圖不足以判斷，查看原始截圖或用瀏覽器原生大小確認。

若整批反覆出現「小框套大框」「主體窄而內線多」「新增部件擠壓原有空腔」，先檢查共同母型、佔幅和細節策略。挑出能代表不同擁擠機制的少量圖示修到原生可讀，再逐顆回查受影響項目；不能只修最顯眼的一顆就把整批升級為通過，也不能繼續用同一缺陷構造擴量。使用者提出的失敗比例是重要回饋，未逐顆核對前不把它改寫成已量測的統計。

原則依據可參考 [IBM UI icons 設計規範](https://www.ibm.com/design/language/iconography/ui-icons/design/)：其 padding 與 key shapes 段落要求避免部件擁擠，並允許為正確物體比例調整佔幅，不強塞進基本形狀。此處的截面預算與回修方法是 Master 的實作推導，不是 IBM 的固定數值規範；設計原則閱讀也不能替代逐顆查看兩份實際來源圖稿。

## Atlas 草稿中的反例

以下是需要回修的配置，並非完成範例或全庫通用數值：

| 反例 | 要解決的空間問題 |
| --- | --- |
| `fuel` 油管平行段與泵身中心距離僅 2／24 | 16px 幾乎沒有淨距。重分配泵身和油管寬度，不能只修油管彎角。 |
| `caravan` 窄門貼近外壁，窗底又靠近輪胎上緣 | 同一局部堆了多層封閉輪廓。重新安排門、窗、輪的位置，或捨去非必要部件，而非逐一縮小。 |
| `backpack` 完整小矩形前袋嵌在窄主袋底部 | 前袋兩側與底邊形成三條窄通道。比較更開放的口袋結構及共享底邊，不固守「大框內放小框」。 |
| `traffic-cone` 錐身底線與獨立底板僅隔 2／24 | 兩條水平線幾乎融合。決定底板是否應成為共同底邊，或給出足夠的實際間隔。 |
| `traffic-light` 小燈圈在 16px 只剩很小的內孔 | 判斷燈孔是否必要；可調整整組燈的比例／間距，或在小尺寸改成清楚的實心燈點。 |
| `ship` 船殼下緣與水波靠得太近 | 水線與船殼各自可辨不代表並置清楚；重排垂直空間或刪掉非必要水波，保持船體主要輪廓。 |

審稿紀錄應寫出具體部件、受影響尺寸、修正策略及尚未解決之處。有這些問題的稿維持待精修；截圖存在、路徑未相交、來源數量足夠或看過放大圖，都不能升級為造型完成。
