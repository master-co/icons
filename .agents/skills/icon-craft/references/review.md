# 審稿與證據

從頭重畫且使用者明確要求不保留舊稿時，遵守 SKILL.md 的從頭重畫模式；下述前稿保存與前後比較不適用於被撤銷的圖稿。以最新稿、既有家族母型及外部來源重新審查，清除舊稿通過標記。

## 先定義變數

A/B 比較一次盡量隔離一個主變數：框角、點徑、內線數、頭身比例或視覺重心。Master 前後稿以同一光學尺寸、viewBox、CSS 尺寸、顏色、背景、DPR、文字與空間比較；4× 診斷圖明確標示倍率。比較不同圖庫時使用相同 CSS 顯示尺寸，保留各自原始 viewBox、描邊與比例，說明母版／顯示尺寸；不能改造上游原稿來製造比較優勢。

修改前先保存必要的 source / dist 或截圖。不要在完成修改後憑記憶畫「before」。若沒有真實 baseline，就只交付現況與理由，明講缺少前後證據。

新圖示的候選稿也是前稿：下一次改稿前保存其可編輯來源、幾何及畫面。審稿輸出可重新生成，既有候選與審查結論不能被靜默覆寫。若新回饋指出某批粗糙，將受影響項目退回待精修，保留舊結論並說明撤回理由；不要僅補文字便維持通過狀態。

## 兩種閱讀距離

原生圖：單顆、同家族、不同結構並排、14 / 16 / 18px 文字旁。先看語意、粗細感、空隙、重心與整組節奏。小圖示必須在實際 CSS 尺寸下檢視；聊天介面可能縮放截圖，需按檔案原始比例開啟。

放大圖：看 tangent、接縫、凹角、端點、重疊和自交。放大能解釋缺陷，不能證明小尺寸可讀。避免只交巨大 SVG 或帶漸層、陰影和旋轉的 hero 卡。

疏密複審時，來源與候選須有同 CSS 尺寸的並列，並保留來源原始描邊。逐項記錄最擁擠的部位、應連接／分離／遮擋的關係、原生是否仍可分辨，以及重排或刪減的理由。大圖可見細縫、數學上未相交，都不能推論原生不黏合。詳見 [空間分配與視覺分離](spacing.md)。

## 完稿後的來源審美回比

來源研究不是畫之前的一次性步驟。每顆新增或修改的圖示畫完後，必須拿**最新稿**與固定來源重新並列，先在同 CSS 尺寸的 16／20／24 看整體，再放大診斷原因；保留來源原始描邊與比例。改稿後再次回比，不能拿舊截圖、記憶或先前已通過的結論代替。

先問「來源與最新稿，哪個整體更成熟、更自然、更有物件神韻？」再具體觀察輪廓張力、部件比例與一體感、視覺重量、負空間、曲線節奏和細節主次。可辨識、間距合格、工程通過或比前稿進步，只是局部證據，不能代替這次審美判斷。

來源即使只略勝，也要找出實際勝點，轉成下一筆可做的修改：例如微調中央拼片與球緣的比例，或把密集網線換成較安靜的網面訊號。提煉它的比例和構造關係，必要時讓候選直接向更好的來源靠齊；不要以「保持不同」「已經畫好了」「統一用了某個圖元」抵抗成熟解法。使用來源的具體造型時依[來源處理](authorship.md)記錄，不能改寫座標後宣稱無來源。

提煉來源優點時，同時保護原稿已成立的簡潔度與辨識性。來源較完整的物理結構，不代表需要照搬全部分割；新增線條須在目標尺寸帶來實際收益，並與原稿再次比較。若比例或曲線微調即可改善，優先保留原有構造；如新增細節反而使整體繁雜，回到較簡潔的版本。例如足球可以保留中央五角片與五條外接縫，微調拼片尺度，不必增加整圈多邊形。這是依用途取捨，並非所有物件都強制減線。

回比須留下簡短的具體結論：來源勝在哪裡、最新稿吸收或保留了什麼、在哪些原生尺寸確認效果、還有什麼差距。若只是兩種合理氣質，說明取捨；使用者已選定方向時以該偏好為準，不退回假稱客觀平手。若仍明顯不如來源，維持待精修並繼續修改，不以文字辯護、分數或數量目標放行。這是製作內部的回修要求，不增加逐顆向使用者索取批准的流程。

## 收錄判斷

逐顆記錄使用位置或可重現的常見操作、所在控制項與相鄰命令，以及目前可以使用的圖示。先將既有圖示放進同一個選單、工具列或狀態欄，以實際標籤、選取狀態和原生尺寸比較。功能存在，本身不足以證明需要專用圖示。若找不到可信使用情境，或無法指出替代後具體會混淆哪兩個動作或狀態，就沿用現有圖示，在本次選圖清單中刪除候選。已收錄的圖示依本次授權處理。

- 對象已由上下文交代時，先試通行的動作圖示。分享面板的「複製連結」用 `copy`，分頁選單的「固定分頁」用 `pin`，多選工具列的「刪除」用 `trash` 搭配選取數量。無須依每種對象、數量或名詞片語再造一顆。
- 狀態與動作分開驗證：「分享」按鈕不能代替「已共享」，「下載」不能證明「可離線」。退收複合狀態圖示前，在實際清單、方格或樹狀結構中保留物件類型與持續可見的狀態；多個狀態可能並存時，也要一起檢視。獨立狀態欄成立，不代表在只容許單一圖示的位置也能直接替代；記明成立的版面與資訊條件，不為退收而改掉使用情境。
- 專用狀態或命令若同時並列，且只能靠圖形區分，才保留必需的差異。例如低、中、高優先度在同一欄顯示，須能在單色、小尺寸下直接分辨各級。錄下鄰項及可見差異，逐顆決定。
- 若歧義來自標籤或資訊架構，先改善用字或顯示狀態。字元面板可直接顯示數學字元或公式範本。替代能成立時，將對照留在審查記錄；只有實際會搜尋該詞時才補關鍵字。

## 母型與複合圖的回查

先拆出主體與動作，再沿 catalog 名稱找到兩者的繪製函式。通過收錄判斷後，例如編輯器的圖片對齊控制應取用 `image` 的山景，待寄郵件應取用 `mail` 的信封和 `clock` 的時鐘。先前退收的連結變體也暴露了造型問題：各自另畫鏈節，丟掉了獨立 `link` 的兩個回彎及交扣處。新寫一條看似鏈條的路徑，未來母型更新時便會分岔。把真正共用的輪廓抽成函式或帶參數的母型，將尺寸、位置、線寬和遮擋留給組合處。

在原生 16px 和支援的粗線端並排看「母型 → 安置後部件 → 複合圖」。先確認安置後仍留得住內孔，再看徽標是否切出殘點或把接縫染黑。若空間不足，先調整主次配置。需要省略次要細節時，讓母型提供小尺寸參數，記下省略的是哪一筆，以及並排後保留了哪些辨識線索。語意確實需要不同構造時，記下用途差異。發現一個重畫的部件，就在這次工作範圍中搜尋其餘使用點，涵蓋名稱裡沒有該物件的複合圖。

## 缺陷分級

| 類型 | 處理 |
| --- | --- |
| 語意錯誤、裁切、非預期斷線、孔洞消失、不可用的輸出 | 修正後才可稱完成 |
| 家族不一致、過密、重心偏、圓角過頭、曲線不順 | 給具體畫面並修整；未解決就標明待審，不偽稱已定案 |
| 可合理分歧的比例／氣質偏好 | 完成可比較候選與理由，供使用者判斷；不虛構通用最佳數值 |

看 bell-off 的斜線是否仍能辨識原母型，settings 的孔是否存活，file-text 是否黑成一塊，star 的角型是否縮小到顯得失衡。這些是對應結構的提問，不是每輪都要求重畫這四顆。

## 自動化能做什麼

附帶 render-review.mjs 會依現有 dist 生成原生明暗／DPR 1、2 圖稿、16px 四倍診斷、文字情境，以及 padded raster 的邊界、墨量與質心。JSON 中的 clip／empty 可當結構缺陷；墨量與質心只作排查線索，不能轉成美感排名或自動置中指令。

腳本不會認出物件、不檢查所有孔洞、不可證明曲線漂亮，也沒有替人類審稿。browser unavailable 時交付 HTML 與明確未驗證狀態；不要把生成成功改寫成視覺通過。

## 一份有用的審查紀錄

兩份來源不是兩個打勾欄位。先找同語意且有代表性的成熟解法；主庫缺少時查其他合適圖庫，再決定是否只能用結構參考。結構參考須指出實際比較的部件，不能拿一般幾何或不相關物件填足數量。並列觀察要說明來源在哪個輪廓、比例、曲線、負空間或接點更好，以及自己的圖稿怎麼處理這個差距；「都有兩輪」「都是雲」只完成語意核對。

物件圖示另檢查簡化前後的形態保真：記錄來源如何用底足、肩部、收腹、口沿或接地帶出物性，以及候選如何保留或改寫。改善留白與減少內線不能單獨構成完成理由；若支承、構造或物件特有輪廓變弱，保留前稿並回修。不同合理器型可有取捨，但須說明選擇，不把語意流失泛稱為極簡風格。方法見[物件語意與形態保真](craft.md#物件語意與形態保真)。

把「來源已比較」「輸出已渲染」「已目視待精修」「造型複審候選」分開。看過截圖而仍有僵硬曲線、失衡比例、近接或粗糙接縫時，記錄缺陷並修正後再升級；腳本不得自動依數量、檔案存在或 hash 相符把圖稿標成視覺完成。未完成本批具體修整與紀錄時，不為追求速度繼續擴量。

記錄用途、辨識線索、混淆概念、概念／變體、固定來源與觀察、虛線及透明度／漸淡的採用或不採用理由、修改、目視證據、結果與剩餘問題。保留不改也須有具體理由。記錄審查者及是否由 AI 執行，將工程通過、目視檢查與維護者定案分開。需要比較時用簡單表格；不要用「8/10 精緻度」之類沒有量測定義的總分。

完成條件是此次要求的圖稿、必要變體、相關驗證和可查看證據俱全。alpha 可交付待設計定案的結果，但須明記已知限制。只完成本次授權範圍，不自動擴大為整庫改稿。瀏覽器與 DPR 覆蓋按實際執行記錄；未啟動或未查看的組合維持未驗證。

## 精修歷史與審查可追溯性

整庫審查不等於整庫修改。逐項記錄保留的具體理由；修改項目另記缺陷、尺寸、處理及新的目視證據。不要把前一輪的「已看過」當成本輪結論，或只改 hash 來使驗證通過。

將審查意見轉成可觀察的判斷，再以其他圖示驗證。例如縮排的內容位移、擴音器／握手的結構曲線、票券撕線的局部端帽，是三種不同問題；不能簡化成「多加弧線與細節」。保存已接受的版本，以具體構造缺陷或新要求為修改依據。任務要求獨立複審時，複審者仍須逐顆檢視，不繼承前輪通過標記；整合者核對修改與證據。

歷史基準保護的是可追溯性，不是永久禁止使用者授權的精修。保存真實 before 與舊 ledger 後，可將「全部圖稿必須不變」改成：本輪未修改項目精確相同；修改項目有明確清單、前後 hash 和審查結果。來源角色若由比較轉為實際沿用／重繪，也要同步 notices、SVG 單檔下載、ZIP 和框架套件，普通圖庫仍不需逐顆顯示來源標籤。
