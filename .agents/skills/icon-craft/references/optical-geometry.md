# 光學尺寸與幾何

## 目前 alpha 起點

先讀 repository 的 packages/icons/src/geometry.mjs 和 docs/design-system.md。下表是 2026-11-16 的預設基準，具體值與後續變更以目前原始碼及設計規範為準。

| 原生母版 | 主描邊 | soft 框角 | rounded 框角 | 主要輪廓 inset 起點 | 獨立元素間隙審查目標 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 16 | 1 | 1 | 2 | 2 | 1.5 |
| 20 | 1.25 | 1.25 | 2.5 | 2.5 | 1.75 |
| 24 | 1.5 | 1.5 | 3 | 3 | 2 |

inset 不是每種圖形都必須滿足的可見邊界；間隙是審稿目標，並非現有圖稿全都被自動量測證實。端帽、尖角與視覺補償要按結構處理。

## 尺寸是圖稿，不只顯示大小

原生母版有各自的 viewBox、線寬、座標與必要的細節簡化。24 縮到 16 的描邊與間隙按比例變小，不等於經過小尺寸設計。non-scaling-stroke 只改描邊縮放行為，也無法替你修正狹窄孔洞或刪掉不必要細節。

小尺寸按辨識優先保留：主輪廓、語意差別、必要狀態。日期格、文字線、資料庫分層等可減少；刪除斜線、plus modifier 或 unlock 的開口若承載語意，不能因簡化消失。簡單 arrow / minus 的三份圖稿可以接近比例關係，毋須為了宣稱光學設計製造差異。

現有例子：calendar 3 / 4 / 6 點；file-text 1 / 2 / 2 行；trash 16 只留一條內線；database 16 移除中間線。例子是設計手段，不是新圖示必須模仿的數量模板。

## 像素與端帽

針對水平／垂直線，中心線 x、描邊 w、device ratio d 的兩側約在 (x ± w/2) × d。兩側能落於整數 device pixel 時邊緣最容易整齊，但分數描邊不一定能兩邊同時對齊。斜線與曲線必然有反鋸齒。不要把全部控制點強行四捨五入成整數，或加 shape-rendering=crispEdges 來宣稱 pixel-perfect。

round / square cap 在開放端點沿方向伸出半個描邊；butt 不延伸。miter 的尖角延伸視角度而變，並受 miterlimit 影響。bbox 要算可見描邊，不只算 path 控制點。SVG stroke 行為以 [W3C painting 規格](https://www.w3.org/TR/SVG2/painting.html) 為準。

Craft 03 的 `clipboard-pen` 曾因筆尖 miter 超出畫布約 0.22–0.24px，而中心線仍在畫布內。移動角落徽標後，要核對九組實際描邊邊界並重看原生圖，不能只檢查控制點或 soft 預覽；保留真實修前稿，讓細微裁切也能追溯。

在 DPR 1 和 2 都看原生尺寸；特別有分數線寬／佈局問題時再看 1.25 / 1.5。不要承諾所有 DPR 同時像整數黑白點陣；優先保持輪廓穩定與細節可讀。

## 圓角是依結構設計的三個預設

sharp：零框角、square cap、miter join。soft：微圓輪廓、round cap/join。rounded：較大輪廓半徑、保留語意尖端。圓形可共用全部幾何；直線在 soft / rounded 可以相同。差異來自整體語氣，不必保證每一張 SVG 都有獨特 path。

現有 contour(points, radius, closed) 在建置時計算切點與圓弧，對相鄰線段裁切加上限。它是作者控制的折線工具，不是任意 SVG 轉換器；曲線、凹角與細結構仍需要作者判斷。修改 radius 陣列或工具本身時，特別查短邊、直線共線、重複點、極尖角與閉合接縫。

對兩條相交直線，內角 θ 的圓角切點距離約為 r / tan(θ/2)。角度越尖，固定 r 會吃掉越長的線段；因此不能用同一框角 r 套星星與方框。這說明局部限縮的必要，不要求作者每次手算全部角。

外框收圓後確認面積與視覺重量；箭頭端部、文件折角、齒輪齒根、房屋頂點各自保留辨識。只換 stroke-linejoin 或把所有 open cap 改成 round，沒有完成三種輪廓。

## 微孔：先決定它是否有用途

閉合圓的可見內徑約為 `2r − stroke`；窄矩形的內寬約為 `width − stroke`。先用它找疑點，再檢視原生 raster；孔的位置、反鋸齒、前景對比與 DPR 都會影響可讀性。不要把「大於 1px」當成全部圖示的通過門檻。

Craft 01 的實際取捨：

| 問題 | 處理 | 邊界 |
| --- | --- | --- |
| chart-bar 的 16px 柱孔僅 0.75px | 局部柱寬 2 → 2.5px，內寬 1.25px，同時重排柱距 | 不改 20／24，也不改全庫線寬 |
| user-cog 中心孔約 0.48px | 擴大內孔，同時擴大齒根與外徑，保留齒環肉厚 | 只擴內孔會與外輪廓相碰 |
| USB 終端、極小人頭、音符頭的孔沒有必要 | 依語意改實心；USB 仍保留圓／方／箭頭三種信號 | 齒輪、放大鏡、拉環等必要孔不能照抄這個簡化 |
| file-archive 的拉環與齒軌擁擠 | 16px 加寬並上移拉環，重排兩齒，僅齒軌用較細描邊 | 主輪廓及拉環維持主描邊；要一起檢查虛線、端帽與 React |

`contact` 原本頭肩的中心線似乎有距離，扣掉兩邊描邊後，16px 可見間隙只約 0.13px。上移、略縮頭部後約為 1px。這是內容區重排，不能只把整個圖示放大；書冊輪廓和裝訂點仍要有空間。

## 虛線的端帽不是全域圓角的附屬品

以撕線或拉鏈齒軌表達切割／機械結構時，短矩形比膠囊更合語意。可對該 path 明確設 `stroke-linecap="butt"`，外框仍用自己的角型。反過來，流動路徑的圓端帽也可能合理；不要訂成「所有虛線一律平切」。

round／square cap 約使每段可見長度增加一個線寬、空隙減少一個線寬；butt 不增加。換端帽後要重看段長，不能只加屬性：原本靠圓帽撐大的極短 dash，平切後可能變成難辨的碎點。Craft 01 的 file-archive 在 16px 重新設定兩個 0.75px 齒段和 1.25px 間隔；ticket 的撕線維持自身較長節奏。這些是已檢視的案例值，不是所有圖示的模板。
