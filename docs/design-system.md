# Master Icons 設計規範 · alpha 0.1

2026-11-16。此文件描述已實作的起稿及待人工審定的標準，不把數值當成美感證明。

## 產品性格

面向 Web / App 日常操作。先做到中性、安靜、清楚，再加入微圓親和感。圓角服務辨識，不能把所有形狀變成膠囊。線條克制、重心穩定，密集介面仍有空隙。

主張是「三種幾何風格 × 三種光學尺寸 × 輕量工程輸出」的一致組合。多圓角與光學尺寸各自都有前例，不宣稱發明了這些能力。

## 尺寸與線條

| 母版 | 描邊 | soft 外框半徑基準 | rounded 外框半徑基準 | 主要用途 |
| --- | ---: | ---: | ---: | --- |
| 16 × 16 | 1.25 | 1 | 2 | 14px 文字、密集表格、工具列 |
| 20 × 20 | 1.5 | 1.25 | 2.5 | 16px 文字、表單、側欄 |
| 24 × 24 | 1.75 | 1.5 | 3 | 18px 文字、較寬鬆操作區 |

這是設計起點，非產業標準。1.75 取常見 1.5 與 2 之間的折衷，仍須搭配文字字重、DPR、明暗背景判斷。不要任意加粗描邊破壞內部空隙。

主要輪廓通常距畫布邊緣約 2 / 2.5 / 3，按形狀補償；可見描邊與中心線不同。獨立元素視覺間隙以 1.5 / 1.75 / 2 為審查目標，尚非全圖自動通過的保證；刻意連接的結點除外。

## 三種圓角

| 風格 | 路徑與端點 | 用途 |
| --- | --- | --- |
| sharp | 框角 0；square cap；miter join，limit=3 | 精準、技術感；圓本體仍為圓 |
| soft | 微圓框角；round cap/join；尖端少量修整 | 預設，理性但不生硬 |
| rounded | 更大框角；round cap/join；保留語意尖端 | 較親和的產品語氣 |

半徑按結構分配，並非每個角使用同一數字。細框、齒輪、箭頭、星星會限縮；圓和直線在 soft / rounded 中可能相同。不為製造差異扭曲形狀。

contour() 在建置時用切點與圓弧生成圓角，每段裁切最多 45%，避免相鄰角吞噬。runtime 不做通用路徑變形。僅改 stroke-linejoin 無法控制實際輪廓半徑。

## 光學尺寸

三種大小各有 viewBox、線寬與座標。簡單符號可以共享比例邏輯，不要求每個座標都刻意不同。密集形狀則調整細節。

| 圖示 | 16px | 20px | 24px |
| --- | --- | --- | --- |
| calendar | 3 個日期點 | 4 點 | 6 點 |
| file-text | 1 行，放寬左右空隙 | 2 行 | 2 行，較長行距 |
| trash | 1 條內部線 | 2 條 | 2 條 |
| database | 無中間分層線 | 1 條中間線 | 1 條中間線 |
| settings | 齒頂角度較寬、調整內圈 | 中尺寸比例 | 完整比例 |

24 母版縮至 16 時，1.75 描邊會變約 1.17；本系統 16 母版用 1.25，並減少部分細節。這是可驗證的結構差異，尚非辨識率勝出證據。

## 家族與檢視

file / file-text、folder / folder-plus 共用外框。bell / bell-off、user / users、lock / unlock 保持相同語彙。modifier 要有可見空隙。先決定主輪廓，再加最少辨識線索；避免寫實細節與裝飾性分割。非對稱形狀允許光學位移，不以數學中心代替目視重心。

原生尺寸判斷優先於四倍放大圖。放大只找接縫、折線與弧度問題。同步檢視淺底、深底、DPR 1 / 2、文字旁與密集清單；不可把 CSS transform 後的畫面當成原生尺寸證據。

## 命名、無障礙與方向

使用 kebab-case 語意名稱；React 使用 PascalCase + Icon。中英搜尋詞不等於 export alias。圖示預設裝飾用途；按鈕已有文字或 aria-label 時不重複朗讀。單獨傳意時使用 label / aria-label。圖稿尺寸不等於點擊目標尺寸。

RTL 依概念決定，僅鏡射 arrow-left/right、chevron-left/right、chevrons-left/right、undo/redo。不自動讀取祖先 dir，需明確傳入 direction。

## 審定門檻

1. 原始 48 與本期清單的全部圖示在九組合中皆可辨識、無意外斷線，風格差異穩定。
2. 全體命名圖稿在工具列、表格、側欄中沒有明顯過重、過輕或重心不協調者。
3. 用實際文字大小與顏色做候選盲測，評估辨識與偏好，記錄審稿人的問題與決定。

Raster tests 通過不取代設計審定；總檔案數不取代概念覆蓋率。

## 目前範圍

原始 48 個名稱固定保留，另依 src/ui-scope.json 增加 162 個通用介面與商務圖示，另有 organization-scope.json 的專案與文件組織10顆，以及 productivity-scope.json 的60顆，共280個命名圖稿。刪除的舊擴充圖稿不恢復；新稿由可讀的家族模組繪製。

## 製作契約補充 · 2026-11-16

必要時允許虛線、透明度與漸淡。虛線用於虛擬邊界、路徑或未完成狀態，段長、間隔與端帽按尺寸審查；透明度與漸淡用於層級與深度，主要辨識輪廓不可因此消失。明暗背景、原生 16px 與低對比色均須檢視；效果不是掩蓋接縫或擁擠的修補工具。

逐顆參考成熟圖庫，保留語意相符的原稿並列，比較主輪廓、頭身比例、曲線切線、端點、負空間與視覺重量。可以依授權採用成熟解法，不為差異化硬造形。實際沿用具體資產時保留來源紀錄及適用 notices，普通圖庫介面不增加逐顆來源標籤。

每顆記錄缺陷、參考、改動、檢查證據與剩餘問題；批次生成不是逐顆審定。全庫精修狀態見 refinement-ledger.json。先修同一家族，避免單顆變漂亮卻破壞整套比例。

目前 flat node 輸出可表達逐筆 opacity、stroke-opacity、stroke-dasharray 與 stroke-dashoffset；漸層 defs／mask 尚未接入，需使用時再實作 ID 隔離、SVG／React 一致性與多個實例測試，不宣稱此契約已自動提供漸層 API。


## 通用介面與商務製作契約

主輪廓先成立，再修比例、重心與負空間。每筆細節都需有辨識用途，避免重疊描邊、近接端點、擁擠孔洞與無意義分割。曲線需檢查接點與切線方向、曲率、凹口、轉折及收筆；必要時重畫整顆。家族共用母型，狀態不任意改變主體大小。

每顆比較至少兩份固定版本的成熟圖稿，記錄用途、混淆概念、來源觀察、採用／不採用虛線與透明度的理由、修改與目視證據。原稿無問題可保留，但須有具體理由。檢視三尺寸、三圓角、明暗、低對比、文字及同家族排列。渲染成功不能自動升級為目視通過。

本期不新增連續漸層或 mask API；逐筆透明度可表達次要層次與漸淡。原始名稱與 API 相容；新項目僅來自明確清單，必要狀態與方向另計命名圖稿，不灌入基本概念數。

## Productivity 01 工藝補充

六組各10顆，逐組來源比較、原生目視與修整。keyboard在16px保留一排三鍵與空白鍵；cpu每邊從三腳減為兩腳；memory-stick減少芯片筆畫；clipboard-list只留一列。file／folder／calendar狀態共用原生母型，mail／calendar-clock／clipboard-pen以幾何切口避讓徽記。

file-archive首稿短桿誤似鎖頭，改為分段齒軌與拉環，主文件框不分段；段長與間距按母版設定，此為前輪作法；Craft 01 已依構造改為三角型皆使用平切齒段。無新增透明度使用，既有chart-area的逐筆透明度保留。

## Craft 01：構造優先的光學精修

本輪審查280顆、精修14顆，其餘266顆幾何保留。完整逐項理由及真實前稿見 [精修紀錄](craft-01.md)。

- 微圓預設不代表全部零件圓化。ticket撕線、file-archive齒軌使用`butt`平切端帽；外框另依sharp／soft／rounded處理。
- 擴音口、彎握柄、手掌與指節的弧形是結構曲線；即使sharp預設也不拉成直線多邊形。
- 小孔先判斷語意：必要孔拓寬並重排周邊；非必要孔可改實心。不得只增加內孔而壓穿齒輪外環。
- 接點從同一座標或圓心／半徑推導，避免靠端帽遮微縫。看的是描邊後的空隙，而非中心線距離。
- 縮排增減以中行相對上下行的內縮／外移共同表達操作，不只翻轉箭頭。
- 歷史基準保留，但使用者授權的精修可變更幾何；未修改項目仍須逐位元相同，修改項目須有前後hash、理由與證據。

可重用方法及適用邊界已同步寫入master-icons v0.4.0的光學、工藝與審稿參考，不以固定孔徑門檻代替原生目視。


## 工藝複審補充（Craft 02）

工具以工作端區分用途：螢光筆的寬平筆尖、鉛筆尖與筆毛不能只靠下方狀態線辨識。筆身可微圓，工作刃則保留適當平直轉角。off／disabled圖稿延續母型的局部曲線與比例，只為遮擋設計必要切口；不要讓狀態版本停留在較粗略的舊造型。

成功案例用來提出判斷問題，不當作所有圖示都要更圓或更複雜的模板。逐顆複審仍應具體記錄保留理由。
